# PromptSH

An AI‑powered, safety‑aware command‑line shell. PromptSH lets you:
- Type natural language and get it translated into safe shell commands
- Use a rich set of built‑in Unix‑like commands implemented in Node.js
- Enjoy AI‑assisted autocomplete backed by a local Ollama model

## Features
- Natural‑language → command translation via OpenRouter (optional)
- Context‑aware autocomplete via Ollama (optional)
- Dynamic command registry; add commands by dropping files into `commands/`
- Session context with history, variables, temp path tracking
- Safety filters (command whitelist + dangerous pattern detector)
- Clean readline UI with prompts and keyboard shortcuts

## Requirements
- Node.js 18+ (recommended)
- npm (or pnpm/yarn)
- Optional for AI translation: an OpenRouter API key
- Optional for autocomplete: a local Ollama instance running at `http://localhost:11434` with a compatible model pulled (configurable in `ai/autocomplete.js`)

## Quick Start
1. Install dependencies:
   ```bash
   npm install
   ```
2. Optionally configure AI features (see Environment Variables below).
3. Run the shell:
   ```bash
   node index.js
   ```

You should see the welcome banner and a prompt like `promptsh:<dir>$`.

### Keyboard shortcuts
- Tab: show suggestions
- Right Arrow: accept selected suggestion
- Ctrl+Space: next‑word suggestion
- Type `exit`/`quit` to leave

## Environment Variables
Create a `.env` file in the project root if you want AI features.

```env
# Enable natural‑language → command translation via OpenRouter
OPENROUTER_API_KEY=your_openrouter_api_key_here
```

Notes:
- If `OPENROUTER_API_KEY` is not set, natural‑language translation gracefully disables and PromptSH will show available commands instead.
- Autocomplete uses Ollama; the URL and model are configured in `ai/autocomplete.js`.

## Usage
- Run built‑in commands, e.g.: `ls`, `cd src`, `grep -i foo *.js`
- Or type natural language, e.g.: “find JavaScript files updated this week and show the last 5 lines” — PromptSH will generate a safe sequence of commands (within a strict whitelist) and run them.

Example session:
```text
🚀 Welcome to PromptSH - Your AI-Powered Shell
Type commands or ask in natural language. Use "exit" to quit.
💡 Autocomplete: Tab for suggestions, Right arrow to accept, Ctrl+Space for next word

promptsh:myproj$ find . -name "*.js" | wc -l
42
promptsh:myproj$ show me the last 10 lines of README files
Generated 1 command(s)
"grep -R ""^#"" --include=README* -n . | tail -n 10": <output>
```

## Architecture
- `index.js`: CLI loop (readline UI, prompt, key bindings) and startup.
- `executor.js`: Parses input, routes to commands, invokes AI translator when unknown.
- `ai/translator.js`: Calls OpenRouter; enforces whitelist and prevents dangerous patterns.
- `ai/autocomplete.js`: Queries Ollama for suggestions; falls back to heuristics and caching.
- `utils/context.js`: Session state (cwd, env snapshot, history, variables, temp paths).
- `utils/autocomplete-ui.js`: Readline UI integration for suggestions.
- `commands/*.js`: Individual command implementations.

## Safety
- Only whitelisted commands can be generated by AI translation.
- Explicit blocks for risky patterns (e.g., `rm -rf /`, disk ops, `chmod 777 /`, etc.).
- Commands run within your current working directory and session context.

## Development
- Add a new command by creating `commands/<name>.js` that exports either:
  - a function `(args, context) => result`, or
  - an object with `execute(args, context)`.
- The executor auto‑registers any `.js` in `commands/` at startup.

Local dev loop:
```bash
npm install
node index.js
```

### Logging & Sessions
- Basic session output is printed on exit (duration, count).
- You can augment logging via your command implementations.

## Troubleshooting
- No autocomplete suggestions:
  - Ensure Ollama is running (`curl http://localhost:11434/api/tags`).
  - Pull or adjust the model configured in `ai/autocomplete.js`.
- Natural‑language translation disabled:
  - Set `OPENROUTER_API_KEY` in `.env` and restart.
- “Command not found” messages:
  - Check the command filename exists in `commands/` and exports correctly.
